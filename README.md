# Кана

Личный тренажёр японского на русском: 46 знаков хираганы, закрепление знакомых букв в любое время, повторение ошибок и Genki I «Знакомство» (7 занятий, 28 слов, грамматика и аудирование).

## Адреса и доступ

Приложение: https://jap-learn-sync.jap-learn.workers.dev/

GitHub Pages: https://hb3p8.github.io/jap-learn/ — только перенос прежнего прогресса и переход к защищённому приложению. Код на `main` проходит тесты; Actions публикует `.pages-build/`, без приложения и записей Genki.

Cloudflare Worker проверяет ключ перед выдачей HTML, модулей, аудио и API. `assets.run_worker_first` всегда должен оставаться `true`. После входа тот же ключ находится в HttpOnly/Secure/SameSite=Lax cookie на 180 дней. В Cloudflare Secret `SYNC_KEY_HASH` хранится только SHA-256 ключа. Сам ключ: `.local/sync-key.txt` (0600), не публикуется и не входит в резервные копии прогресса.

## Сохранение

Каждый ответ и переход немедленно сохраняется локально и запускает отправку в D1 с объединением быстрых изменений в окне 250 мс. Изменение во время отправки запускает следующую запись. Сетевые ошибки повторяются автоматически с увеличением интервала до минуты; возвращение сети и фокуса запускает проверку сразу. При уходе со страницы используется best-effort keepalive; неотправленное остаётся локально и отправляется при следующем открытии.

Неизменяемые снимки UUID и связи родителей сохраняют обе конкурентные ветки. При конфликте пользователь выбирает версию; история остаётся в D1. Состояние Genki добавляется к старому сохранению без сброса XP, букв или незаконченного занятия.

Старый адрес Pages использует прежнее localStorage, синхронизирует его с D1 и отправляет ключ в POST формы входа на Worker. Ключ не попадает в URL. Если ключа нет, перенос просит его ввести. Из повреждённого или конфликтующего сохранения автоматический переход не выполняется.

## Локальный просмотр

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

http://localhost:4173 — локальный просмотр. Для записи Genki нужны подготовленные закрытые аудиофайлы. Для проверки настоящего входа/сохранения использовать `wrangler dev` с отдельной локальной базой, никогда не тестировать фиктивный прогресс в production.

## Записи Genki и подготовка

Оригинальные PDF не входят в сайт. 8 MP3 из пользовательского комплекта второго издания находятся в игнорируемом `dist/assets/genki/`. 28 отдельных произношений слов создаются голосом Kyoko; 56 записей хираганы и примеров также используют Kyoko.

```sh
node scripts/prepare-genki-audio.mjs '/absolute/path/to/Genki second edition'
```

Нужны macOS `say` с Kyoko и FFmpeg. Оригинальные записи, `.local/`, `.dev.vars` и снимки прогресса не добавлять в Git.

## Публикация

Node.js 24+, зависимости `npm ci`. Существующая авторизация Wrangler должна иметь `workers_scripts:write` и `d1:write`.

```sh
npm test
npm run worker:deploy
```

Скрипт собирает `.local/private-site/`, присваивает версию ссылкам на все модули и стили и развёртывает Worker с уже существующей базой из `worker/wrangler.generated.json`. Ключ и база не заменяются. Сначала публиковать Worker, затем отправлять изменения в GitHub для обновления страницы перехода.

Для первичной установки: подготовить аудио, выполнить `npm run build:private`, затем `npm run cloudflare:setup`. Повторное развёртывание существующей установки выполняется через `npm run worker:deploy`.

## Проверки

`npm test` проверяет хирагану, доступное до срока закрепление, Genki и повторение ошибок, миграцию старого состояния, автоматическую отправку и повторные попытки, конкурентные записи, защиту приложения/MP3 и вход по cookie. Worker-тесты используют настоящую SQL-схему в SQLite. Браузерные проверки выполняются на отдельном локальном Worker/D1.

Учебные источники: [docs/learning-sources.md](docs/learning-sources.md).
